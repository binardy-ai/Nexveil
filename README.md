> **Nexveil** — Xray-прокси для роутера. Внутри роутера панель по-прежнему
> называется `xraypanel`: так называется пакет `opkg`, каталоги и служба,
> чтобы установка и самообновление работали без ломки. Nexveil — это её имя.

# Nexveil — панель Xray-прокси для роутеров OpenWrt

Панель ставится обычным пакетом (`.ipk` там, где пакетами управляет `opkg`,
`.apk` на OpenWrt 25.12 и новее) и открывается с любого устройства в сети:
`http://<IP роутера>/cgi-bin/xraypanel`. Внутри — одна CGI-страница и
shell-скрипты; ни Python, ни PHP, ни Node на роутере не нужны.

> **Это бета-версия.** Панель рабочая и уже используется каждый день, но развитие
> не остановлено: от версии к версии что-то меняется, какие-то места могут вести
> себя не так, как ожидается. Если нашли ошибку, что-то не работает или есть
> идея — открывайте Issue в репозитории. Тесты, замечания и помощь только
> приветствуются.

## Где работает

- **OpenWrt 21.02 и новее, ImmortalWrt и сборки на базе OpenWrt** — проверено на
  ImmortalWrt 23.05.4 (x86_64),(ramips/mt7621); на других версиях и архитектурах работают те же
  пакеты `xray-core` и `uhttpd`, отдельных сборок панели не требуется (панель —
  это shell-скрипты и CGI);
- нужен установленный **Xray** (`opkg install xray-core`, на системах с `apk` —
  `apk add xray-core`) и CGI в `uhttpd` (в стандартной сборке OpenWrt уже
  включён);
- наружу панель открывать не обязательно — достаточно локальной сети или
  доступа по обратному туннелю (реверс-мост, см. ниже).

## Установка

Формат пакета зависит от версии системы:

- **OpenWrt / ImmortalWrt до 24.10** (и вообще всё, где пакетами управляет
  `opkg`) — файл `.ipk`, команды `opkg`;
- **OpenWrt 25.12 и новее** (там пакетный менеджер уже `apk`) — файл `.apk`,
  команды `apk`. Старые `.ipk` в этих системах не ставятся вообще.

Последняя версия — в разделе **Releases**. Ссылка
`https://github.com/binardy-ai/Nexveil/releases/latest` всегда ведёт на самый
свежий релиз, номер версии в ней указывать не нужно. В каждом релизе по четыре
файла: `xraypanel_all.ipk` и `xraypanel_all.apk` (они всегда последняя сборка) и
такие же с точным номером версии — например `xraypanel_0.67.7_all.ipk`.

### Команда для файла .ipk — системы с opkg (до 24.10)

Скачивает `.ipk` из последнего релиза и ставит его. Через `wget` (в OpenWrt и
ImmortalWrt он есть всегда — это busybox):

    wget -q -O /tmp/xraypanel.ipk https://github.com/binardy-ai/Nexveil/releases/latest/download/xraypanel_all.ipk && opkg install --force-reinstall /tmp/xraypanel.ipk

Через `curl` (он стоит не во всех сборках, но если есть — результат тот же):

    curl -sL -o /tmp/xraypanel.ipk https://github.com/binardy-ai/Nexveil/releases/latest/download/xraypanel_all.ipk && opkg install --force-reinstall /tmp/xraypanel.ipk

### Команда для файла .apk — системы с apk (25.12 и новее)

Скачивает `.apk` из последнего релиза и ставит его. Через `wget`:

    wget -q -O /tmp/xraypanel.apk https://github.com/binardy-ai/Nexveil/releases/latest/download/xraypanel_all.apk && apk add --allow-untrusted /tmp/xraypanel.apk

Через `curl`:

    curl -sL -o /tmp/xraypanel.apk https://github.com/binardy-ai/Nexveil/releases/latest/download/xraypanel_all.apk && apk add --allow-untrusted /tmp/xraypanel.apk

`--allow-untrusted` нужен потому, что пакет собран сторонним проектом, а не
подписан ключом OpenWrt. В терминале так ставить можно, а загрузка файла через
веб-интерфейс на этих системах не проходит — там ключа нет.

### Одна общая команда — для любой системы

Если не хочется выяснять, какая у тебя система: команда сама смотрит, чем
ставятся пакеты, скачивает из последнего релиза файл нужного формата и сразу его
ставит. Заодно сама выбирает, чем качать — `wget` или `curl`. Версию указывать не
нужно — всегда берётся последняя.

    M=$(command -v apk >/dev/null 2>&1 && echo apk || echo opkg); E=$([ "$M" = apk ] && echo apk || echo ipk); U=https://github.com/binardy-ai/Nexveil/releases/latest/download/xraypanel_all.$E; if command -v wget >/dev/null 2>&1; then wget -q -O /tmp/xraypanel.$E "$U"; else curl -sL -o /tmp/xraypanel.$E "$U"; fi && { [ "$M" = apk ] && apk add --allow-untrusted /tmp/xraypanel.apk || opkg install --force-reinstall /tmp/xraypanel.ipk; }

Терминал на роутере — это вход по SSH (`ssh root@<IP роутера>`) либо «Терминал»
в самом веб-интерфейсе роутера.

### Способ без терминала: скачать файл на компьютер

1. Открыть раздел **Releases** и скачать оттуда пакет: `.ipk` — для
   OpenWrt / ImmortalWrt до 24.10, `.apk` — для OpenWrt 25.12 и новее.
2. В веб-интерфейсе роутера открыть **Система → Менеджер программ →
   Загрузить пакет** (System → Software → Upload Package), выбрать скачанный
   файл и нажать «Установить».

   На 25.12 и новее этот шаг может не пройти: пакет `.apk` не подписан, а
   система проверяет подпись. Тогда ставьте командами выше, в терминале.

После установки панель открывается по адресу
`http://<IP роутера>/cgi-bin/xraypanel`.

Если `opkg` ругается на зависимости (например, ещё не установлен `xray-core`):

    opkg install --nodeps /tmp/xraypanel.ipk

Переставить ту же версию:

    opkg install --force-reinstall /tmp/xraypanel.ipk

Обновить панель можно и прямо из неё: страница «Статус» → блок про версии
(положить пакет в `/tmp` или загрузить файлом) либо кнопка «обновить» в блоке
самообновления.

Кратко, что чему соответствует:

| Система | Менеджер | Файл в релизе | Установка файла из терминала |
| --- | --- | --- | --- |
| OpenWrt / ImmortalWrt до 24.10 | `opkg` | `xraypanel_<версия>_all.ipk` | `opkg install --force-reinstall <файл>` |
| OpenWrt 25.12 и новее | `apk` | `xraypanel_<версия>_all.apk` | `apk add --allow-untrusted <файл>` |

Удалить панель (настройки и конфиг Xray при этом остаются):

    opkg remove xraypanel

Пакет `.ipk` — это gzip-архив, содержимое можно посмотреть так:

    cd /tmp && tar tzf xraypanel.ipk

## Что умеет

**Выходы (серверы)**

- VLESS + Reality, VLESS + WebSocket, Shadowsocks, Hysteria 2 — добавить,
  изменить, выключить, удалить;
- добавление вставкой ссылки `vless://` — поля заполняются сами;
- проверка задержки (живой замер в миллисекундах), «выбрать лучший по пингу»,
  режим автовыбора балансировщиком (`leastPing` / `leastLoad`);
- подписки: добавить ссылку, обновлять вручную или по расписанию (cron).

**Реверс-мосты (обратные туннели)**

- два способа сразу: **старый** (по домену, `reverse.bridges`) и **новый**
  (VLESS Reverse Proxy по тегу, Xray 25.9.11 и новее);
- панель сама определяет, что умеет установленный бинарник Xray, и пишет в
  конфиг только поддерживаемый способ — служба не падает при смене сборки;
- для трафика из туннеля выбирается, куда его выпускать: только домашняя сеть,
  домашняя сеть + интернет или конкретный сервер;
- на странице «Реверс» есть краткая инструкция: какой способ с какой сборкой
  работает и почему версии Xray на роутере и на портале должны совпадать.

**Правила и наборы**

- правило: кто идёт (устройство) → куда относится трафик (набор) → через что
  выходим (сервер, «по лучшему пингу», напрямую, заблокировать);
- наборы адресов и доменов с типами: IP-адрес или сеть, домен с поддоменами,
  ровно этот домен, слово в имени, шаблон (regexp), готовый список доменов
  (`geosite`) или адресов (`geoip`);
- записи набора правятся прямо в таблице, набор включается и выключается
  целиком, порядок правил меняется перетаскиванием;
- **подбор правила по домену**: вводите домен — панель показывает, в каких
  готовых списках он есть, какое правило его поймает и что перекрыто выше;
- **живые лампочки**: видно, какое правило и какая запись набора реально поймали
  трафик (вспышка и плавное затухание за 30 секунд);
- **списки из правил разбираются на месте**: домены — из `geosite.dat`, адреса —
  из `geoip.dat` (`/etc/xraypanel/geosite.<ИМЯ>.domains`,
  `geoip.<ИМЯ>.cidr`); по ним панель проверяет условия точно, а не «по выходу»;
- обновление баз `geosite`/`geoip` из интернета в один клик или по расписанию
  (Loyalsoldier, v2fly, runetofreedom) — со сводкой и журналами.

**Прозрачный режим и DNS**

- перехват трафика клиентов, всей сети или самого роутера (nft/iptables);
- правила ставятся «на пробу» с автооткатом, если не подтвердить;
- DNS: перехват в туннель, свои резолверы, блокировка DoH/DoT, журнал запросов
  (по нему панель и понимает, какие сайты куда ушли).

**Статистика и обслуживание**

- трафик по клиентам, по выходам и по правилам, история переключений;
- применение конфига: генерация → проверка `xray run -test` → бэкап →
  перезапуск; откат на любую из последних копий;
- **самообновление панели**: проверка новых версий на GitHub, список изменений и
  установка кнопкой;
- темы оформления (светлая, тёмная, WinXP, «плитки», боковое меню), звук
  нажатий, удобная работа с телефона.

## Первые шаги

1. «Серверы» — добавить выход (вставкой ссылки `vless://` или руками) и проверить
   задержку.
2. «Маршруты» — создать наборы («Прямые», «Прокси», «Блок») и правила, которые на
   них ссылаются; сюда же — подбор правила по домену.
3. «Прокси» — включить прозрачный режим для нужных устройств.
4. «Статус» — нажать «применить конфиг» и убедиться, что служба работает.

Панель по умолчанию без пароля и доступна всем в локальной сети. Пароль
ставится на странице «Настройки».

## Правила и наборы: как это устроено

Правило отвечает на три вопроса: **кто идёт** (устройство) → **куда относится
трафик** (набор) → **через что выходим** (сервер, «по лучшему пингу», напрямую,
заблокировать).

**Набор** — список того, что обрабатывается одинаково. Обычно делают три:
«Прямые» (сайты и подсети), «Прокси» (зарубежное например-:)) и «Блок» (реклама и
трекеры). Выключатель набора действует сразу на все правила, которые на него
ссылаются.

Внутри набора лежат **записи**. У каждой — «принцип» (тип) и значение:

| принцип | что означает |
|---|---|
| IP-адрес или сеть | `8.8.8.8`, `10.0.0.0/8` |
| домен и все поддомены | `youtube.com` — сам домен, `www.youtube.com` и прочие поддомены |
| только ровно этот домен | `vk.com` — совпадает буквально, без поддоменов |
| слово в имени | `google` — где встречается такое слово |
| шаблон | `.*\.ru$` — по регулярному выражению |
| готовый список доменов | `youtube`, `category-ru`, `rutube` — из файлов роутера |
| готовый список адресов | `ru`, `private` — из списка адресов |

Что важно знать:

- принцип и значение записи правятся прямо в таблице набора: поменяли выпадающий
  список или текст и нажали «сохранить изменения записей»;
- одна запись может содержать несколько значений: при добавлении пишите каждое с
  новой строки (или через запятую) — панель разложит их в отдельные записи;
- при добавлении записи по умолчанию выбран готовый список доменов — в
  большинстве случаев нужен именно он;
- включить или выключить можно и запись, и набор целиком (кнопки ⏸/▶);
- изменения попадают в Xray только после кнопки **«применить конфиг»** — пока она
  красная, в конфиге ещё старая версия.

Рядом есть блок **«Подобрать правило для домена»**: вводите домен — панель
показывает, в каких готовых списках он есть, какое правило его поймает и что
перекрыто правилами выше по списку. Найденный домен можно скопировать (короткий
клик) или добавить в текущий набор (задержать на секунду).

## Реверс-мосты и версии Xray

Мост — это обратный туннель: роутер сам подключается к серверу-порталу, и через
него снаружи можно зайти на сервисы роутера (LuCI, SSH, панель). Способов два:

| Способ | Что это | Какие сборки Xray понимают |
|---|---|---|
| старый | по домену, `reverse.bridges` | до 26.4.18: 24.12.31, 26.4.17 и подобные. В 26.4.25 его уже нет |
| новый | VLESS Reverse Proxy по тегу, `"reverse": {"tag": …}` у выхода моста | 25.9.11 и новее: 26.4.25, 26.9.9 и подобные |

Панель определяет возможности установленного бинарника сама (даёт ему тестовый
конфиг и запоминает ответ) и пишет в конфиг только поддерживаемый способ. Если
нужны оба способа сразу — нужна сборка, которая понимает и старое, и новое
(например 26.4.17).

Важно для нового способа: **версии Xray на роутере и на портале должны быть
совместимы**. Проверено: портал 26.9.9 с мостом 26.4.17 не работает —
соединение в панели есть, а ответы не возвращаются. Держите на портале и на
роутере близкие версии.

## Готовые списки (geosite / geoip)

Названия списков панель берёт из файлов самого роутера (`/usr/share/xray/*.dat`),
поэтому подсказки всегда совпадают с тем, что умеет ваш Xray. Списки, которые
стоят в правилах и наборах, панель разбирает на месте: домены — в
`/etc/xraypanel/geosite.<ИМЯ>.domains`, адреса — в `geoip.<ИМЯ>.cidr`. По этим
файлам она точно понимает, какое правило поймало трафик.

Разбирать списки нужно один раз; после обновления баз панель разбирает их заново
сама. Обновление баз из интернета (Loyalsoldier, v2fly, runetofreedom) можно
запускать вручную или по расписанию — старая база сохраняется рядом как `.bak`.

## Самообновление панели

Панель умеет проверять новые версии в этом репозитории:

1. раз в сутки (и по кнопке) она смотрит последний релиз;
2. если версия новее — на странице «Статус» появляется предупреждение;
3. кнопка «что нового» показывает список изменений, кнопка «обновить» скачивает
   пакет и ставит его (настройки, серверы и правила не трогаются).

Адрес репозитория и автоматическую проверку можно изменить на странице
«Настройки».

## Сборка из исходников

    ./build.sh
    ./build-apk.sh      # дополнительно пакет в формате apk (OpenWrt 25.12+)

Проще собирать обе версии одной командой — она же проверяет оба пакета и
складывает копии с постоянными именами в `dist/`:

    APK_BUILD_HOST=root@<IP роутера> \
    APK_BUILD_SSH_OPTS="-i ~/.ssh/id_xraypanel" \
    bash build-all.sh

Скрипт собирает `xraypanel_<версия>_all.ipk` из папки `package/` и описания в
`control/`. Версия берётся из строки `Version:` в файле `control/control`.
`build-apk.sh` собирает тот же пакет в формате `apk` (для систем, где пакетный
менеджер уже `apk`): он берёт данные из `build/data` после `build.sh` и требует
`apk-tools 3` — если статического `apk.static` нет, скрипт разово скачает его из
репозитория Alpine (бинарник статический, работает в любом Linux) или возьмёт
путь из переменной `APK_STATIC`.

**Сборку `apk` запускайте только от root** (проще всего — прямо на роутере).
Внутри пакета `apk` записывает владельца файлов, и при сборке обычным
пользователем файлы на роутере окажутся у `nobody`. Скрипт такую сборку
запрещает и подсказывает команду.

## Что лежит в репозитории

- `package/data/` — то, что попадает в пакет (панель, скрипты, конфиг-заготовка);
- `control/` — описание пакета, зависимости и скрипты установки;
- `build.sh` — сборка пакета;
- `ИСТОРИЯ-ВЕРСИЙ.md` — что менялось в каждой версии;
- `КОНТЕКСТ.md` — рабочая тетрадь проекта (состояние, договорённости, проверки);
- `old-versions/` — отменённая линия версий.

## Файлы на роутере

- `/www/cgi-bin/xraypanel` — сама панель (CGI, работает через uhttpd);
- `/usr/lib/xraypanel/*.sh|awk` — генерация конфига, применение, реверсы, готовые
  списки, проверки;
- `/etc/config/xraypanel` — настройки и модель (серверы, мосты, правила) в UCI;
- `/etc/xray/config.json` — итоговый конфиг Xray (генерируется панелью);
- `/etc/xraypanel/` — состояние: списки, кэши, журналы, резервные копии;
- `/etc/xraypanel/config.*.bak` — резервные копии конфига.
