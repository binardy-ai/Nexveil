# Nexveil 0.67.7

Кнопка «обновить» на системах с `apk` (OpenWrt 25.12 и новее).

## Что было не так

Обновление панели из самой панели на роутере с ImmortalWrt 25.12 заканчивалось
отказом: в журнале установки было «скачанный файл не похож на пакет панели — не
ставлю».

Проверка скачанного файла знала только формат `.ipk` — архив с файлом
`debian-binary` внутри. Пакет `.apk` — это контейнер другого вида (`ADB`), и
панель считала его мусором. Получалось, что на всех системах с `apk` кнопка
«обновить» не работала никогда.

## Что сделано

- проверка пакета и чтение версии понимают оба формата: `.ipk` разбирается как
  раньше, у `.apk` проверяется начало `ADB`, а версия берётся из имени файла
  (`xraypanel_<версия>_all.apk`);
- установщик сначала пробует обычную ссылку на файл и идёт в API с токеном
  только если она файл не отдала. Раньше любой токен в настройках включал
  «приватный режим», и обновление ломалось из-за старого токена — именно это и
  случилось;
- если вместо пакета пришло что-то другое, панель пишет в журнал начало ответа
  (например, текст ошибки GitHub) и подсказывает очистить поле «токен GitHub»,
  если репозиторий публичный.

## Как обновиться, если кнопка не работала

Один раз поставьте пакет из терминала роутера — дальше кнопка «обновить» будет
работать:

    M=$(command -v apk >/dev/null 2>&1 && echo apk || echo opkg); E=$([ "$M" = apk ] && echo apk || echo ipk); curl -sL -o /tmp/xraypanel.$E https://github.com/binardy-ai/Nexveil/releases/latest/download/xraypanel_all.$E && { [ "$M" = apk ] && apk add --allow-untrusted /tmp/xraypanel.apk || opkg install --force-reinstall /tmp/xraypanel.ipk; }

При установке панель сама переключит адрес репозитория на `binardy-ai/Nexveil` и
уберёт из настроек старый токен, если он там остался.

Или скачать файл на компьютер из раздела **Releases** (`.ipk` для систем с
`opkg`, `.apk` для 25.12 и новее) и поставить его из веб-интерфейса роутера:
**Система → Менеджер программ → Загрузить пакет**.
